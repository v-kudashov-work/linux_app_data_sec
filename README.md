# app_data_sec — Защита пользовательских данных в Linux с помощью eBPF

**app_data_sec** — это система защиты пользовательских данных от несанкционированного доступа с использованием технологии eBPF (Extended Berkeley Packet Filter) и LSM (Linux Security Module). Решение обеспечивает контроль доступа к защищённым папкам на уровне ядра, блокируя операции чтения, записи, удаления и переименования для процессов, не входящих в список разрешённых.

# Версия 0.5.7

## Основные возможности

- 🔒 **Защита папок** — блокировка доступа к указанным директориям для всех процессов, кроме разрешённых 
- 📋 **Совместимость** Блокировка доступа происходит в дополнение к стандартным правилам доступа к файлам Linux
- 📋 **Администрирование** Доступ root не ограничивается (UID=0)
- 📋 **Белый список приложений** — возможность указать программы, которым разрешён доступ для каждой из защищённых папок отдельно
- 👤 **Поддержка домашних директорий пользователей** — автоматическое применение правил ко всем пользователям (`~/.folder`)
- 🔄 **Динамическая перезагрузка** — автоматическое применение изменений в конфигурации без перезапуска системы
- 📊 **Детальное логирование** — запись всех попыток доступа с указанием PID, пути, inode и дерева процессов
- 🛡️ **Watchdog** — мониторинг состояния сервиса и уведомление пользователей при сбоях
- 🏃 **Высокая производительность** — работа на уровне ядра с минимальными накладными расходами
- 👤 **Для разработчиков** — автоматическое добавление конфигураций от разработчиков других программ

## Архитектура
```code
┌────────────────────────────────────────────────────┐
│ Пользовательское пространство                      │
├────────────────────────────────────────────────────┤
│ app_data_sec_loader     │ app_data_sec_watchdog    │
│ (управление BPF)        │ (мониторинг сервиса)     │
├─────────────────────────┼──────────────────────────┤
│ app_data_sec_merge      │ app_data_sec_unprotect   │

│ app_data_sec_messages   │ /etc/app_data_sec.conf   │
│ (логирование в syslog)  │ (конфигурация)           │
└─────────────────────────┴──────────────────────────┘

┌────────────────────────────────────────────────────┐
│ Ядро Linux (eBPF)                                  │
├────────────────────────────────────────────────────┤
│ LSM хуки:                                          │
│ - inode_getattr - file_open                        │
│ - path_unlink - path_rmdir                         │
│ - path_mkdir - path_rename                         │
│ - inode_create - inode_mkdir                       │

│ eBPF карты:                                        │
│ - folder_config_map - конфигурация папок           │

│    - разрешённые программы                         │
│ - log_level_map - уровень логирования              │
└────────────────────────────────────────────────────┘
```

## Требования к системе

- **Ядро Linux**: версия 5.8+ с поддержкой BPF LSM и BTF (CO-RE)
- **Архитектура**: x86_64
- **Дистрибутивы**: ALT Linux, Ubuntu, Debian. Возможно будет работать, но не тестировалось: RHEL/CentOS. Не работает: Fedora.
- **Зависимости**: libbpf, libelf, zlib, clang, bpftool

# Конфигурация
  В папке /configs/ содержатся конфигурации для некоторых популярных программ. Импортировать всё можно командой:
```bash
  sudo app_data_sec_merge_config ./configs/
```

или запустить установку с ключом --with_defs для интерактивного режима импорта конфигураций:
```bash
  sudo install_app_data_sec.sh --with_defs
```


    Формат конфигурации:
    Конфигурационный файл: /etc/app_data_sec.conf

```text
# enable = yes|no — включает или отключает защиту
enable = yes

# Защита папки и список разрешённых программ
protect /home/user/.secret_folder /bin/konsole /usr/bin/bash
protect ~/.test_app /bin/my_app
```
  
    Формат записи protect
    protect <путь> [разрешённая_программа1] [разрешённая_программа2] ..

    <путь> — абсолютный путь к защищаемой папке или ~ для домашней директории

    разрешённая_программа — абсолютный путь к программе, которая может обходить защиту 
        (получает доступ к этой папке, если доступ есть на основе стандартных правил доступа к папкам linux)


## Директива scan_mount

Директива `scan_mount` предназначена для автоматического обнаружения новых папок при монтировании файловых систем.

### Синтаксис
```conf
scan_mount <путь>
```

### Параметры

- **путь** - путь к папке, появление которой нужно отслеживать. Не поддерживается использование `~` для домашней директории - все пути должны быть абсолютными.

### Как это работает

1. Сервис периодически проверяет существование указанных путей (каждую 0,5 секунды)
2. При обнаружении пути (например, после монтирования USB-флешки или сетевого диска) выполняется полное сканирование
3. В результате сканирования применяются все правила `protect`, которые соответствуют найденным путям

### Примеры использования

```conf
# Отслеживание внешних носителей
scan_mount /mnt/external
scan_mount /media/usb

# Отслеживание сетевых разделов
scan_mount /mnt/nfs/share

# Пути с пробелами
scan_mount "/mnt/My Drive"
```

## Автоматическая конфигурация для разработчиков других программ (Auto-config)

Если вы разработчик, вы можете добавить автоматическую конфигурацию для своего приложения. 
Вот как это сделать:

Для автоматического применения конфигураций при установке/обновлении используется директория `/etc/app_data_sec.autoconfig/`.

Все `.conf` файлы из этой директории автоматически импортируются в основную конфигурацию при запуске `install_app_data_sec.sh` без необходимости подтверждения.

```code
# Создание автоконфигурации
sudo mkdir -p /etc/app_data_sec.autoconfig/
sudo chown root:root /etc/app_data_sec.autoconfig/
sudo chmod 750 /etc/app_data_sec.autoconfig/
sudo cp my_config.conf /etc/app_data_sec.autoconfig/
```

В программе для sh или другой программе после этого вам нужно вызвать
```code
sudo app_data_sec_merge_config --autoconfig
sudo app_data_sec_loader --rescan
```
если они существуют, чтобы применилась конфигурация. Если этого не сделать, конфигурация применится не сразу, а в течении 15 минут.

Пример:
```code
if [ ! -d "$AUTOCONFIG_DIR" ]; then
    mkdir -p "$AUTOCONFIG_DIR"
    chown root:root "$AUTOCONFIG_DIR"
    chmod 750 "$AUTOCONFIG_DIR"
fi

# Проверяем наличие merge_config и запускаем, если есть
if command -v app_data_sec_merge_config &> /dev/null; then
    # Запускаем merge_config с autoconfig директорией (тихо, без лишних сообщений)
    app_data_sec_merge_config --autoconfig -y 2>/dev/null || true
    app_data_sec_loader --rescan # Отправляем комманду на пересканирование конфигурации и файлов
else
    # Утилита не найдена - просто игнорируем (не ошибка). Конфиг будет применён при установке app_data_sec
    echo -e "${YELLOW}[INFO]${NC} app_data_sec_merge_config not found, skipping autoconfig import"
fi
```

Так же желательно подождать 5 секунд в установщике для того, чтобы применились файлы конфигурации.

# Принудительная перезагрузка конфигурации и сканирование (--rescan)

Для принудительной перезагрузки конфигурации и сканирования всех защищаемых папок и применения актуальных правил можно использовать ключ `--rescan`.

Этот механизм позволяет:
- Применить изменения конфигурации
- Применить изменения в файловой системе без перезапуска сервиса
- Обнаружить новые папки, созданные после последнего сканирования
- Обновить inode файлов после их пересоздания
- Проверить наличие новых программ в белом списке

```bash
# Отправить сигнал на пересканирование
sudo app_data_sec_loader --rescan
```

## Слияние конфигураций
# Слияние одного файла
```bash
sudo app_data_sec_merge_config /tmp/new.conf
```

# Слияние всех .conf файлов из директории
```bash
sudo app_data_sec_merge_config /etc/app_data_sec.d/
```

# Удаление защиты
```bash
# Создание файла со списком для удаления
echo "protect /home/user/.secret_folder" > /tmp/remove.conf
```

# Удаление
```bash
sudo app_data_sec_unprotect /tmp/remove.conf
```

# Отключение
Чтобы отключить модуль, можно установить 
    enable = no
в файле конфигурации /etc/app_data_sec.conf

# Просмотр всех защищённых папок
```bash
sudo app_data_sec_unprotect -l
```

# Логирование
Уровни логирования (параметр -l при запуске app_data_sec_loader):

    0 — логирование отключено

    1 — только заблокированные попытки доступа (по умолчанию)

    2 — все попытки доступа (разрешённые и заблокированные)

Для просмотра логов в syslog используется сервис app_data_sec_messages
sudo journalctl -u app_data_sec_messages -f

Чтобы перенаправить вывод eBpf модуля в системный лог, можно запустить app_data_sec_messages_to_syslog из суперпользователя:
```bash
sudo app_data_sec_messages_to_syslog
```

или запустить в консоли:
```bash
sudo cat /sys/kernel/debug/tracing/trace_pipe
```

# Watchdog
Watchdog (app_data_sec_watchdog) отслеживает состояние основного сервиса. При его остановке на рабочем столе пользователей создаётся файл app_data_sec_errors.txt с инструкцией по восстановлению.

sudo ./uninstall_app_data_sec.sh

# Безопасность
    Работа на уровне ядра — защита от обхода на пользовательском уровне

    Проверка дерева процессов — блокировка доступа через родительские процессы

    Поддержка root — доступ root не ограничивается (UID=0)

    Защита от подмены — использование inode для идентификации файлов
    
# Ограничения
    После установки приложения, которое участвует в конфигурации папки для защиты, может понадобиться подождать 15 секунд перед запуском приложения. Это время необходимо для обновления данных модуля.
    Не поддерживаются программы-скрипты python и sh. Можно использовать, если запустить их в родительском процессе обычного исполняемого файла и настроить доступ к нему.
Для модуля eBPF
```text
    #define MAX_PROTECTED_PATHS 5000   - максимальное количество защищаемых папок
    #define MAX_ALLOWED_PROGRAMS 20  - сколько исполняемых файлов возможно для каждой папки из MAX_PROTECTED_PATHS
    #define MAX_DEPTH_FOR_APP 8 - максимальный уровень вложенности путей исполняемых файлов
    #define MAX_DEPTH_FOR_PATH 64 - максимальный уровень вложенности путей защищаемых папко
    #define MAX_NAME_LEN_FOR_LOG 10 - только для логирования, максимальная длинна имени файла
    #define MAX_LOG_PATH_LEN 128 - максимальная длинна пути для логирования команды запуска исполняемого файла
    #define MAX_DEPTH_FOR_APP_LOG 4 - максимальная вложенность для логирования вложенности процесса
```

Для loader
```text
    #define MAX_LINE_LEN 1024 - максимальная длина строки в файле конфигурации
    #define MAX_PATHS 5000  - максимальное количество защищаемых папок
    #define MAX_ALLOWED 20 - сколько исполняемых файлов возможно для каждой папки из MAX_PROTECTED_PATHS
    #define MAX_PATH_LEN 256 - максимальная длинна пути к файлу или папке
    #define CHECK_INTERVAL 5 - период проверки конфига на наличие изменений
    #define RETRY_INTERVAL 15 - период проверки файлов на доступность или удаление
    #define MAX_SCAN_MOUNT_PATHS 500 - Максимальное количество путей для scan_mount
    #define MAX_HOME_USERS 1000 - Максимальное количество папок в папке /home/ (количество пользователей)
```
